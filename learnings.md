# Project Learnings — Sample Academy AI Content System

Self-learning log. Read at the start of every task; update after every task. When an entry has been confirmed multiple times or is older than 30 days, graduate it into a `wiki/concepts/` or `wiki/entities/` page and replace it here with a one-line reference. Keep this file lean (< 50KB).

## What Has Worked

- **TDD red→green→prove loop (confirmed 2026-05-27).** For each code fix: write the test encoding the bug/edge case → run and CONFIRM it fails (red) → implement → run and CONFIRM green by reading the actual output, not the exit code. This caught real bugs (#59 fail-closed, #62 injection guard) and even caught a brittle order-dependent regex in my own test before it gave a false pass. Pair with `gitnexus impact <fn>` before editing + `detect-changes` before commit.
- **Lean board-driven batches (confirmed 2026-05-27).** GitHub Issues = source of truth; work 1–3 related issues per batch → mini-plan → TDD → prove → commit to master → close issue with an evidence comment (commands + output reviewed). Keeps progress visible + trackable; avoids big-bang.
- **Claude-as-judge gates over artifact checks (confirmed 2026-06-09).** Schema/render/audio checks pass "word soup" and even shipped a *wrong video* + typography defects. The 3-gate DoD (A fidelity · B teaching · C watch-the-MP4) with `gate:status` enforcement caught both. Judge = headless Claude Code (no key); Gemini only flags. **Caveat that bit us:** a frame-sampling visual review that checks content+brand but NOT *typography* waves through clipped glyphs / orphan punctuation / overlap → geometry needs its own DOM-measured gate (#73). Architecture/tooling rationale now in [[architecture-decisions]].
- **Systematic fix > in-place patch, proven on #72/#73 (confirmed 2026-06-09).** The typography defects were fixed by moving leading/spacing/safe-area onto shared scales in `brand/tokens.ts` (every scene primitive inherits them) AND adding an automated DOM-measured gate — not by patching QuoteCard alone. Result: the defect class can't recur on future videos. The pattern: when a bug is a *class*, fix the contract + add the sensor. Now [[layout-integrity-gate]].
- **DOM-measured gate via Remotion's real DOM (confirmed 2026-06-09).** Because Remotion renders real DOM in headless Chrome, a probe component (`LayoutProbe`) mounted behind an input prop can `getBoundingClientRect` every element at sampled frames and emit it over `onBrowserLog` — giving a deterministic geometry gate (no-clip/safe-area/overlap) without a vision model. Reusable pattern for any "did it render correctly" check.
- **Background agents inherit plan-mode write-lock (confirmed 2026-06-09).** Subagents dispatched during a plan-mode session can't write files even after the main thread is executing; they stage full file contents in their plan file (`# FILE n:` + fenced block) and the main thread extracts/verifies/commits. Keep the staging format machine-parseable. Prove-don't-trust: extract and re-run checks, never commit on agent say-so.
- **Standalone service decoupled from the Next.js app (confirmed 2026-06-09).** The student bot (`bot/`) vendors the small pure brain modules (retrieval, citation guard, persona) and shares only the `content/tools` *data*, rather than cross-importing `chatbot/`'s Next.js internals. A separate Cloud Run deployable is cleaner self-contained; the expensive/valuable part (curated data + retrieval/citation design) is what's reused. Now [[standalone-bot]].
- **No-footage lessons render end-to-end (confirmed 2026-06-10).** Locked decision (`CLAUDE.md` → "Lesson Production Model — No Human Footage"): every delivery type is animated, no recordings. Proven on `topic-1-lesson-2` — a 🟩 demo beat renders as `comparison-chats` (same prompt → 3 tool windows, animated) and a 🟧 talking-head as `quote-card` + TTS. The "BLOCKED ON INSTRUCTOR" framing was a stale strategy assumption; the Remotion pipeline never had an external-footage path.
- **Hand-curate the capability-table; never auto-derive it (confirmed 2026-06-10).** Letting `capability-table` auto-derive cells from the tool JSONs (cellFor → Y/-) produced a near-uniform wall of ✓ that *defeats the scene's teaching purpose* (no "Best" tier → the narration had nothing to point at) AND surfaced unsourced cells (Perplexity image-gen, all-✓ Agents). Gate C (watch) caught it → FIX. Fix: author explicit `content` with a differentiated **B/Y/-** grid (each tool ≥1 `B`, weak cells `-`, free-tier-honest), and keep the table caption reinforcing *differentiation* not "fundamentals are shared." Auto-derivation is fine for `tool-card-reveal` (names/taglines) but NOT for the decision chart.

- **Design→render conversion is the load-bearing build step (confirmed 2026-06-25, cloud-design handoff).** Claude Design returns **design-altitude** `scene-contract.json` (sceneType + loose `copy` intent + `narration.gist` + timing + motion notes) per `course-planning/contracts/planning-to-render.md`. These do NOT render. The build step (Claude Code) maps each scene's `copy`/`gist` into the **render-strict** `content` + full `narration.text` shape its sceneType requires (`content/schemas/scene-types.ts` → `SCENE_CONTENT_SCHEMAS`), producing `content/lessons/<id>/lesson.json`. Then the 6-stage DAG: `plan-lesson` (or direct authoring) → `tts:lesson` → `align:lesson` → `render-lesson` → `gate:status` → `publish-to-drive`. Expand `gist`→full narration at the **2.96 wps word budget** (8-min ≈ 1210 words) and fact-check tool/pricing claims (Gate A). The inbound package (`Drive/.../inbound from cloud design/`) carries validated contracts + a `_realignment/REALIGNMENT-PATCHES.md` file + a new-component request. Built lessons only get corrected *plans* from patches — the MP4 still needs a re-render to reflect them.
- **Overnight render+build orchestration (confirmed 2026-06-25).** Build ALL cheap durable artifacts first **in parallel** (new components, scene-contract patches, every designed lesson's `lesson.json`) while the machine is free — these don't render and don't contend. THEN run renders **serially in one background queue** that does `tts→align→render→gate` per lesson keyed to its own `batch.done` (renders own the machine; a self-contained per-lesson serial pipeline is the only place gating is safe — never gate a different lesson while one renders). A 90-min wake-up heartbeat (ScheduleWakeup) monitors the queue log for stalls + continues building; `agent-ops/overnight-supervisor.sh` is the bash watchdog alternative (don't run both). Reference-repo scan (Agent-Reach/no-mistakes/headroom) added nothing the existing builder/checker/Codex + STATE.json + heartbeat loop lacks — render output validation = existing `gate:media`/`verify:render`, render watchdog = existing `RENDER_TIMEOUT_MIN`, Codex-fallback = existing `awaiting_codex_review` + Claude-judge Gate C.

## Conventions / gotchas (lesson authoring)

- **Locked label names use AMERICAN spelling.** Use American spelling (e.g. color, organize) everywhere on screen and in narration. The watch gate (Gate C) flags British spelling as a fidelity defect against the locked label set.
- **Scene entrances glide in from opacity 0 over ~1s** (spring `useGlideIn`), so the first ~8 frames (~0.27s) of any scene are warm-linen-blank before the eyebrow appears — this is the motion contract, present on every lesson. The headless watch judge sometimes samples that frame and over-reports it as a "blank frame … up to 2s" defect. **Adjudicate with frame evidence** (`ffmpeg -ss <t> ...`): if the fully-blank window is sub-second and content is full by ~1s, and Gate L passes, it's the standard entrance, not a defect — record Gate C PASS citing the measured frames. (Potential future polish: drop the `Eyebrow` glide delay so the first element appears in ~2 frames.)
- **Video output dirs: `out/*` are lessons+sizzle; `output/video/*` are the platform-walkthrough + brand-showcase (separate composition) — search BOTH when auditing videos (confirmed 2026-06-26).** Two distinct render trees exist and an audit that scans only one will wrongly report a video "missing" (the platform walkthrough was reported missing 3× for exactly this reason — it lives in `output/video/`, not `out/`). Full map now in [[video-output-map]]. Quick version: **`out/`** = current lesson/sizzle renders (`topic-N-lesson-M.mp4`, `sizzle-16x9/9x16.mp4`, `module-1*.mp4`); **`out/v2/`** = the v2 facelift pass (the lessons + sizzle); **`out/v3/`** = the in-progress design-QC pass (never overwrites `out/*`); **`output/video/`** = `platform-walkthrough.mp4` (60s, comp `PlatformWalkthrough` = 1800 frames in `src/compositions/PlatformWalkthrough.tsx`, registered in `src/Root.tsx` as id `"PlatformWalkthrough"`) + `brand-showcase.mp4` (comp `BrandShowcase` = 300 frames). The walkthrough + showcase are from May 13–15, **NOT up to standard** (`color_space=bt470bg`, not BT.709; pre-v2/v3) — both need a BT.709 re-render. They are a *different output dir AND different compositions* than the lessons. (There is also a designed `course-planning/platform-walkthrough-sizzle/` scene-contract — a separate planned sizzle, not the rendered MP4.)

## What Has Failed

- **`tool-demo` / `comparison-chats` scene `caption` collides with the global narration caption chip on SHORT scenes (2026-06-10).** Both sit in the bottom band; when the scene content is short (1–2 `tool-demo` outputs), the scene's static `caption` drops into the narration chip's band → text-on-text overlap. Gate C (frame watch) catches it; Gate L's sampled frames can MISS it (timing-dependent). Taller scenes (3 outputs, e.g. 1.3) keep the caption clear, so they pass. **Rule:** prefer OMITTING the `caption` field on `tool-demo` scenes — the narration already carries the line. If you want it, only use it on tall (3-output) scenes. Bit `topic-1-lesson-5` (tool-demo scenes).


- **Single `regenerate` pass after a narration edit ships STALE audio (confirmed 2026-06-10).** `regen-graph.buildLessonNodes` snapshots the *current* `lesson.json` to compute each `tts:<scene>` node's `inputs:[text]` BEFORE the `plan` node regenerates `lesson.json` in the same pass. So when you edit `script.json` narration and run `regenerate` once: `plan` rebuilds (new lesson.json) but `tts` still hashed the OLD text → marked "fresh" → audio not re-synthesized, while the video/captions update → **audio↔visual mismatch** (caught on `topic-1-lesson-2` by mtime: wav older than script.json). **Workaround:** run `npx tsx scripts/plan-lesson.ts <id>` FIRST (updates lesson.json out-of-band), THEN `regenerate` — or run `regenerate` twice. Proper fix (follow-up): make the `tts` node read its text at `inputs()` call time from the freshly-planned lesson.json, or order plan strictly before node-set construction.

- **Silent render after an outline/cell edit — `align`-staleness (confirmed 2026-06-10, same class).** `align` is the step that injects `narration.audioSrc` + word timings (and the *measured* durations) INTO `lesson.json`. `plan` rewrites `lesson.json` with narration **text only** (no audioSrc). So when you edit the outline (e.g. capability-table cells — NOT narration) and `regenerate`: `plan` re-runs (outline changed) → writes text-only lesson.json; but `align`'s inputs (the WAVs) are unchanged → `align` marked **fresh/skipped** → audioSrc is **dropped and never restored** → the render muxes a **silent** AAC track (ffprobe mean_volume ≈ -91 dB) AND uses the wrong (estimated, longer) duration. The render still "succeeds" (exit 0) and looks perfect on frames — only the watch gate's audio sensor catches it. Bit v2 and v5 of topic-1-lesson-2. **Note:** running `plan-lesson` manually (the workaround for the tts bug above) TRIGGERS this one. **Safe recipe for the fan-out:** after ANY edit to a lesson's outline/script, do a **clean full rebuild** — `del content\lessons\<id>\.regen-cache.json` then `regenerate` (runs plan→tts→align→render in order, audioSrc present, correct duration). Always confirm audio before gating: `ffmpeg -i out/<id>.mp4 -af volumedetect -f null -` (mean_volume should be ~ -20 to -35 dB, NOT -91), or check `lesson.json` has 1 `audioSrc` per narrated scene. The watch gate (Gate C) needs a Whisper key to auto-confirm audio; without it, it flags "no narration" as FIX — so verify audio out-of-band.

- **Gate L on estimated durations ≠ Gate L on the aligned build (confirmed 2026-06-10, bit several lessons).** `gate:layout` after `plan-lesson` samples each scene's settled frame at `0.8 × estimated_duration`; after a clean rebuild, `align` writes the *measured* (longer/shorter) durations, so the sampled frame shifts AND the narration caption shown at that frame changes. A pre-flight PASS can therefore become a FIX on the real MP4. **Two structural overlap causes, both on tall content meeting the always-on bottom narration caption:** (1) `feature-grid` row heights are set by the *tallest card in the row* — a card whose `sub` wraps to 2 lines makes its whole row tall and pushes lower rows down into the caption band (so shortening one bottom card's sub doesn't help; the row above is the culprit); (2) long `quote-card` quotes push the attribution into the caption band. **Rules for data scenes:** keep `feature-grid` to ≤4 cards when any sub wraps (or ≤6 with one-line subs that clear by ≥40px); keep `quote-card` quotes ≲55 words; and **always re-run `gate:layout` on the post-rebuild (aligned) lesson, not just the pre-flight** — treat the pre-flight as a cheap early filter, the aligned run as the gate of record. `recap-grid` is a single-row flex (designed for 3 cards; 4 fits, 5+ overflow the right safe inset) — use `feature-grid` for 5+ inventory items.
- **8-card `feature-grid` collides with the bottom narration caption (confirmed 2026-06-10).** A full 8-card grid (4 rows) reaches y≈900 even with `sub:""`, overlapping the caption chip. 6 cards with subs (3 rows) is the safe max that clears. When the source calls for more steps than fit, drop *repeated-capability* steps (keep one per distinct step) and document it as a layout-forced production decision in Gate A/B — teaching fidelity is preserved, only redundancy is cut.

- **Gate L's settled-frame sampling can miss caption-chip overlaps even on the aligned build (confirmed 2026-06-10, bit one lesson's cover in review).** The narration chip's width and text change every page (~1.4s); Gate L samples ONE frame per scene, so an overlap that exists at 0:14 can be absent at the sampled frame → PASS while the shipped video overlaps. **Rule: don't rely on the PASS alone — read the probe rects.** Any text in the x≈320–1600 band must keep its bottom edge above y≈865 (chip top ≈892 with a 1-line page; chips grow upward); design scenes with ≥30px clearance. The cover stat row + bottom axis labels are the recurring offenders.
- **Syne's lowercase `g` descender is intrinsically tiny — it reads as "cut off" but is NOT a render clip (verified at 6x zoom, 2026-06-10).** No `overflow:hidden` exists in the scene chain; the ink is present with free space below it. It's the typeface's design (display face; compare the long `y` tail in "days." vs the stub `g` hook). At 40–56px + h264 it looks amputated. Any fix is a *brand* decision (secondary reading face for captions/body), not a CSS patch — flagged to Instructor, don't "fix" unilaterally.
- **Voice lane is verbatim, never paraphrase.** Quoted outline lines must be carried word-for-word — a paraphrase can invert the author's meaning. The lesson plans mark these beats cadence-critical; treat quoted text in course-map rows as untouchable source.
- **`audit-quadrant` (16th scene type, 2026-06-10):** a two-axis grid scene with task pills plotted per quadrant.
- **Gate T + depth targets (2026-06-10, fable-overhaul).** DoD is now **A·B·C·L·T**: `gate:timing` compares the MP4 duration to `course-map.json` **`lesson.minutes`** (the top-level field — NOT the row-minute sum). PASS 75–120%, WARN 60–75%/120–130% (blocks publish, exit 0), FIX outside (exit 1). Measured corpus TTS pace = **2.96 words/sec** (±10% across the corpus) → authoring word target = `minutes × 60 × 2.96 × 0.85`; an 8-min lesson ≈ 1,210 words. The old short cuts were ~350–520 words — depth comes from full-row narration + one demo scene per capability at walkthrough pace, NOT padding.
- **`screen-flow` (17th scene type, 2026-06-10):** animated mock-screen click-through (window chrome, spring cursor glide→dwell→click pulse, char-streamed typing, split/full layouts, `fidelity: cartoon|hybrid`). Design rules in `animated-lesson/references/08-simulated-screen-contract.md`. Use for builder walkthroughs and dashboard page-throughs; `tool-demo` stays for prompt→output reveals. `targetPositions` omitted = cursor hidden (safe fallback).
- **Subagent mining outputs must be verbatim-verified before use (2026-06-10, bit the evidence-packet pass).** The mining agent fabricated a plausible "Instructor quote" (a story with invented numbers) by reconstructing it from assumptions.md context; the writer agent's mandatory spot-check against the raw source extract caught and dropped it. Rule: VERBATIM-marked material in `content/lessons/*/evidence.md` was source-verified at write time; any new mining pass must re-verify quotes against the raw extract — never trust a summarizer's quotes.
- **Visual-only edit rebuild order: regenerate → align-lesson → regenerate (2026-06-12, bit twice).** The two-pass regenerate fix solves narration edits and scene-set changes, but NOT the align-staleness class: an outline-only (visual) edit makes `plan` rewrite lesson.json text-only (audioSrc dropped, estimated durations) while `align` stays "fresh" → silent 493s render. Running plan-lesson/align manually BEFORE regenerate doesn't help — regenerate's plan node re-runs (outline hash changed) and clobbers the align. The working order: `regenerate` (plan+render, knowingly silent) → `align-lesson` (restores audioSrc + measured durations) → `regenerate` (render only; plan now cache-fresh). Always volumedetect after. Proper code fix still owed: make the align node hash lesson.json's narration text-state.
- **TTS pronunciation guards leak into screen copy (2026-06-12).** Letter-spaced guards (e.g. "A P I", "S Q L") belong in narration ONLY; authoring agents copied them into outline `content` strings → rendered on screen. Scan before render: `/\b(?:[A-Z] ){1,}[A-Z]\b/` over outline content. Narration keeps the spacing; titles/uiState/prompts read "API"/"SQL".
- **Word-budget pre-flight is live (2026-06-12).** `generate-script --check` now FAILS scripts under 75% of `course-map minutes × 60 × 2.96` (proven: an old 343-word script → SHORT vs floor 1066). Budget is also embedded in the generation prompt (`buildScriptPrompt` budget param) and per-beat targets belong in lesson-plan beat tables (`lesson-plan/references/pacing-and-depth.md`). Three layers: prompt → pre-flight → Gate T.
- **Feature-grid bottom-row subs near the caption band (reconfirmed 2026-06-12 at 2-row/5-6-card layouts).** Drop the bottom-row `sub` fields (set `''`) — cat+title carry the card; narration carries the detail. And recap-grid's 3–4-card limit bit again (five recap items clipped off-frame): 5+ recap items = feature-grid with true numbering, never recap-grid.

- **Overnight lesson re-render "took all night" — three independent root causes, all now fixed (confirmed 2026-06-21).** A multi-lesson v2 re-render ran ~2h48m and one lesson failed. Diagnosed from the render log; encode all three so it isn't re-discovered:
  1. **Rendering is THE bottleneck and renders are long.** Lessons are a few minutes each (thousands of frames at 30fps); the batch ≈ 70 min of finished 1080p video. A full serial re-render is inherently ~2–3h — that is normal, not a hang. Never assume "an hour"; size expectations off frame counts (`render.start` logs `frames`).
  2. **Never run heavy compute while a render is live.** The first batch ran concurrently with the full test suite + repeated `gate:motion`/`gate:media` (ffmpeg+sharp) + frame extracts → per-lesson time **tripled** (251s alone → 802s) and the batch crashed. Rule: during a render the box is RESERVED — gate AFTER, never during.
  3. **Memory pressure fails renders outright.** At ~85% RAM (other projects open) one lesson died with `delayRender("…frame…") not cleared after 28000ms` — a starved headless Chrome can't advance a frame in time. Knobs now in `scripts/render-lesson.ts`: `RENDER_CONCURRENCY` (cap parallel frames, e.g. 2–4) and `RENDER_FRAME_TIMEOUT_MS` (default 120000, up from Remotion's 30000). Lower concurrency / free RAM on a loaded box.
  - **Monitoring lesson (why it sat unreported all night):** the completion watcher used a 2h wall-clock timeout < the 2h48m job, so it expired partway and never signaled "done" — the render finished at 12:11 AM but nobody was told. **Rule: key long-job completion to the job's own `batch.done`/process-exit, never a wall-clock guess; set any watcher timeout well above the worst-case run.**
  - Efficiency follow-ups (queued review): parallelize renders across fresh processes (memory permitting), cache the Remotion bundle (rebuilt every run), add a perf benchmark (frames/sec, peak RAM, wall-clock per lesson) so concurrency is tuned, not guessed.
- **Motion/liveliness is now gated — videos must not be slideshows (confirmed 2026-06-21).** The v2 facelift's "settle in ~7s then HOLD" rule (to satisfy the still-frame layout gate) made the sizzle + lessons static. Fixed by a continuous `SceneAmbient` layer in `SceneFrame` (all scenes) + `AmbientGlows`/floats in `SizzleManifesto`, and enforced by `gate:motion` (`activePct ≥ 0.6`, no still held > 2.5s), now run by `publish-to-drive`. Full contract: `.planning/MOTION-CONTRACT.md`. Don't ship `useFade`-only / settle-and-freeze beats.

- **Design fidelity: the HTML-vs-Remotion-MP4 "dull/soft" gap is NOT color (confirmed 2026-06-22).** When a Claude Design HTML prototype looks crisper/more vivid than the Remotion MP4, do NOT chase color tokens or color-space — the core palette is byte-identical sRGB hex on both sides and an uncompressed `renderStill` measures CIE2000 **ΔE ≈ 0** vs the design hexes (`scripts/_sizzle-color-de.ts`). The gap, in priority order: (1) **resolution/DPI** — HTML at devicePixelRatio ≥ 2 (retina) vs a flat 1920×1080 raster; fix = render at 2× (3840×2160) then downscale (SSAA); (2) **codec** — h264 4:2:0 chroma subsampling desaturates/softens saturated crimson `#8B2635` on linen `#EDE8E3` (MP4 only; raise bitrate / lower CRF, BT.709, yuv444p only if Teachable plays it); (3) **implementation/motion** — shadows, gradient stops, SVG stroke widths, font AA (bundled TTF vs CDN), and timing (compare code `spring`/`interpolate` vs HTML easing — stills can't show motion). **Diagnostic seam:** pair uncompressed `renderStill` PNG vs same-frame MP4 PNG — wrong-in-renderStill = fixable implementation, only-wrong-in-MP4 = codec. Bundle + review prompt in `claude-design-delta/`. Now → [[design-fidelity-html-vs-mp4]].
- **`/design-sync` does not apply to this repo (confirmed 2026-06-22).** Design-sync expects a buildable UI component library (Storybook or esbuild-bundlable package → compiled `dist/`). This repo is a Remotion *video* pipeline (root build = `remotion bundle`); scene comps are frame-driven (`useCurrentFrame`/`<Sequence>`) and don't render as standalone UI, and the only "design system" is loose CDN-React JSX from the original Claude Design session. To keep Claude Design on-brand, ship a **context bundle** instead (`claude-design-context/`: `tokens.css` + guidelines), not a sync. Recorded in `.design-sync/NOTES.md`.
- **Codex `codex exec` is currently un-runnable on this Windows box (confirmed 2026-06-22).** Its child PowerShell processes die with exit `-1073741502` (0xC0000142 DLL-init) in BOTH `--sandbox read-only` AND `--dangerously-bypass-approvals-and-sandbox` — so codex can't read files to review and returns a BLOCK that means "couldn't review," NOT a finding. Plain PowerShell spawns fine from the shell, so it's codex's exec wrapper, not the box. Two prior runs flailed for hours on web/GitHub fallbacks before BLOCKing. Mitigations: bound any codex prompt to fail-fast (no web/GitHub; BLOCK immediately if a local read fails); if it can't review, mark `awaiting_codex_review` and proceed (never hang, never fail open). See memory `project_codex_sandbox_windows`.
- **Google Drive "Date" column lies; verify delivery by content (confirmed 2026-06-22).** After `publish:drive`/a manual copy, Windows Explorer shows the Drive file's **createdTime**, not modifiedTime, so an updated file can look stale. Confirm a delivery by the **cloud API** (Drive `search_files` → `fileSize` + `modifiedTime`) or by `md5sum` of the mounted file vs the source — never the Explorer date. Proven on the v2 sizzle (cloud reported the new 13.1 MB / 01:02 modifiedTime while Explorer showed 6/20).

- **`gate:status` GREEN can be STALE — re-run `gate:layout` after any render-affecting change (confirmed 2026-07-09, hail-mary ship).** `gate:status` only READS the cached `review/*.md` (A·B·C·L·T); it never re-measures. A code change that alters the rendered DOM (a v4 motion path, a SceneAmbient edit, a component refactor) silently invalidates the Gate-L artifact while `gate:status` keeps reporting the old PASS. Bit us hard: many lessons showed `PUBLISH OK` on `layout-gate.md` files written *before* the SceneAmbient/clip conflict existed; a FRESH `gate:layout` FAILed all of them. **Treat a cached PASS whose code has changed as UNKNOWN, not green — re-render + re-gate before shipping.** Same freshness class as the `align`/`tts` audio-staleness traps above. Graduated → [[layout-integrity-gate]].
- **SceneAmbient (and any bleeding `overflow:hidden` layer) must be `data-decor` (confirmed 2026-07-09).** Gate L's clip rule flags EVERY non-decor `overflow:hidden` box whose content overflows. `SceneAmbient`'s `inset:-200` glow overflows its full-frame box by ~200px → clip violation on every scene of every lesson. Fix = `data-decor` on the container (gate exempts decor); probe-only attribute, **zero pixel change → no re-render needed for the fix**. Any ambient glow / watermark / accent bar that deliberately bleeds needs `data-decor` from day one.
- **Corpus is NOT as gated as claimed — only some lessons have a review bundle (confirmed 2026-07-09).** Most lessons have NO `review/` dir at all → `gate:status` can't pass → unpublishable, regardless of rendering. Generating a bundle = Gate L/T (automated) + Gate A/B/C (LLM judges via headless `claude -p` incl. WebFetch fact-check — heavy on the user's token budget). An old README claim that the videos were "gate-checked" was flagged unverifiable by the stakeholder persona; now confirmed false. Corrected in [[video-output-map]].
- **Corpus ledger is now the only valid "review complete" claim (2026-07-15).** `npm run corpus:ledger` enumerates the full launch corpus (the topic-* lessons), prints per-lesson A·B·C·L·T state + an N/N summary, and writes `.planning/CORPUS-LEDGER.md`; exit 0 only at N/N green. Born from an over-claimed-completion incident — CLAUDE.md "Done Means Done" section holds the six enforcement rules (full-corpus scope, printed ledger, EVIDENCE lines, re-derive at claim time, certifier ≠ claimant, no rounding up stragglers). Baseline at creation: 3/7 green.
- **v4 motion system + Cover-variant overflow (2026-07-09).** v4 is an additive `lesson.motionProfile: 'v3'|'v4'` seam (absent = v3, byte-identical): scene-exit glides (LessonVideo `SceneExitWrapper`), QuoteCard word-synced progressive reveal, per-topic Cover variants. **Cover variants 1-3 were HELD BACK** — they are content-height-unaware; variant 3 narrows the title, wrapping it taller, and with SceneFrame's vertical centering the column exceeds 1080 → title above frame / stats below (Gate L fail, t1l1). ## Patterns and Preferences

- **Tech stack (2026-05-26).** Remotion v4 (React video rendering) · Next.js 16 App Router + TypeScript (web app `chatbot/`) · Anthropic Claude SDK (AI backend) · Zod 4 (validation/schemas) · Cheerio + robots-parser + p-limit (content ingestion) · Tailwind CSS 4 + CSS custom properties (styling) · Vitest (testing) · Docker (node:22-bookworm-slim) + FFmpeg (container). Brand tokens: Syne font, #EDE8E3 base, #8B2635 accent, 4px radius.
- **Architecture: lessons are codified data.** A lesson is fully version-controlled data; changing the data regenerates the affected script/animation/voiceover surgically via a 6-stage, content-hashed generation DAG (outline → script → plan → TTS → align → render). No re-recording. See [[codified-lesson-pipeline]]. The conceptual core is [[timing-inversion]] (audio length drives scene duration, not hand-authored frames).
- **Generation backend abstraction.** Web-driven generation goes through a `GenerationProvider` selected by `GENERATION_BACKEND`: `claude-code` (default, dev — spawns headless `claude -p`, no API key) or `anthropic-api` (production). The chatbot reaches the pipeline by **spawning root scripts** rather than cross-package imports. See [[studio-generate]].
- **Container-first, TDD-enforced.** Docker from day 1; the Stop-hook script (`.claude/hooks/stop-gate.py`, when enabled) + CI block a turn/push unless typecheck + lint + test pass on the changed slice. Build vertical slices (data → logic → UI) ending green with render/screenshot proof — never horizontal half-built layers.
- **Audit integrity (P0).** Never mark work complete without verifying features exist, connect, and have tests. Fact-check gate blocks unverifiable tool claims; renders fail loudly on violated invariants rather than shipping silently.
- **Knowledge stack is layered.** Three systems run together: `learnings.md` (fast, mutable working memory) → `wiki/` (curated, searchable, index-first knowledge that mature learnings graduate into) → GitNexus `.gitnexus/` (code-structure knowledge graph for impact analysis and navigation). Check the wiki first when a graduated learning would answer a question.

- **Docker Desktop dockerInference wedge (2026-07-03).** Docker AI's Inference manager crash-loops the whole daemon when it can't remove its stale AF_UNIX socket (`%LOCALAPPDATA%\Docker\run\dockerInference`, "file cannot be accessed by the system"). Fix: quarantine the `run` dir (rename — the sockets defeat del/fsutil) + set `EnableDockerAI=false` in `%APPDATA%\Docker\settings-store.json`. Better: TTS now runs Docker-free via `TTS_NATIVE=1` + `TTS_PYTHON=<py3.12 venv>\Scripts\python.exe` (kokoro requires python <3.13; venv at `<py3.12 venv>`).
- **Audio presence ≠ freshness (2026-07-03).** `align-lesson` happily stitches whatever WAVs exist onto CURRENT narration text — if TTS silently failed, lesson.json gets valid-looking audioSrc/words pointing at audio that SPEAKS THE OLD WORDS. Preflights must check freshness (wav mtime vs lesson.json; or grep aligned words for the new text), not just presence.
- **OneDrive can eat root files after a crash-reboot (2026-07-03).** After a pagefile-exhaustion crash + restart, ~19 tracked ROOT-level files (package.json, CLAUDE.md, .gitignore…) vanished from the working tree; subdirectories untouched. Recovery: `git ls-files --deleted -z | git restore --pathspec-from-file=- --pathspec-file-nul` (restores only deleted, preserves modified). Check `git status` before any `add -A` after a crash.
- **Windows EBUSY on shared task logs (2026-07-04).** A scheduled-task .cmd that redirects stdout to the same file the child opens with `appendFileSync` kills the child instantly (EBUSY double-open). Wrapper redirects must target a DIFFERENT file than the app's own log.
- **Resumable launchers must archive only STALE outputs (2026-07-04).** An unconditional "archive then re-render" step re-archived 20 fresh renders on relaunch and restarted the whole queue. Guard: archive only when the mp4 is older than its lesson.json.
- **Renders depend on fonts.gstatic.com (2026-07-04).** A ~4-minute Google Fonts outage burned all 3 retry attempts of one lesson (delayRender timeout fetching Syne). Backlog: self-host the font. Until then: a fast mb:0 triple-fail during renders may be network, not code — retry later before debugging.
- **SceneFrame centers; variable-height scenes must top-anchor (2026-07-04).** AssignmentList overflowed the caption band because vertical centering halves the effect of any content-height reduction; fixed with an additive `justify="flex-start"` prop + density tiers. Any future tall-variable scene type should top-anchor from day one.
