# Phase 8.5: Ingestion Control Panel

## What We're Building

A web UI control panel on the content viewer page (or as a sub-page) that exposes the Phase 4 ingestion pipeline to non-CLI users. Currently all ingestion operations require running npm scripts or Docker commands — this phase puts controls in the browser.

## Features

### P0 (This Phase)

1. **Data Freshness Indicator** — show per-tool "last updated" date, visual staleness indicator (green/yellow/red based on age), overall repo freshness score
2. **Manual Refresh** — button to trigger a poll for a specific tool or all tools (calls the ingest:poll pipeline)
3. **Ad Hoc Search** — search bar to pull data from established sources for a specific tool or topic (calls the ingest:search pipeline)
4. **Schedule Status** — show whether scheduled polling is active, when last run was, when next run is

### P1 (Future — "Down the Line")

5. **Custom Sources** — add sources beyond the established vendor docs list. User can input a URL or domain, system scrapes it and maps to tool schema
6. **Source Management** — view/edit/delete established sources, add new ones
7. **Ingestion Log** — show history of past ingestion runs with results (success/skip/error per source)

## Technical Approach

The ingestion pipeline (Phase 4) is all Node.js scripts that run on the host or in Docker. The control panel needs to:
- Read freshness data from the Git-versioned tool JSON files (check file modification dates or embedded metadata)
- Trigger ingestion runs by calling the CLI scripts (via a server API route that spawns the process)
- This introduces a server-side component that can execute shell commands — needs careful security boundaries

### Architecture Options (to be discussed in planning)

A. **API routes in the chatbot Next.js app** — add /api/ingest/* routes that shell out to the ingest scripts
B. **Separate admin service** — dedicated lightweight server for ingestion control (keeps chatbot clean)
C. **Static freshness only** — show freshness data in the UI but trigger refreshes via CLI (compromise approach)

## User Direction

- "Scheduling controls on the AI tool repository page"
- "A sub-window or slider to show how fresh the data is"
- "Pull new data and potentially search ad hoc from regular sources"
- "Down the line: custom sources or reach out beyond the established list"
- "Basically we just need a control panel"

## Dependencies

- Phase 4 (Content Ingestion — complete): scraper, diff engine, CLI, Docker scheduling
- Phase 6 (Content Viewer V2 — complete): the page where controls would live
