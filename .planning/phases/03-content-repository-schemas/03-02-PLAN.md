Create `src/lib/scene-types.ts`:
- Define `SCENE_TYPES` as a const array with all 13 scene type strings: `"cover"`, `"journey-map"`, `"comparison-chats"`, `"tool-card-reveal"`, `"capability-table"`, `"setup-checklist"`, `"feature-grid"`, `"voice-demo"`, `"recap-grid"`, `"preview-band"`, `"demo-cue"`, `"dig-deeper"`, `"assignment-list"`, `"quote-card"`
- Define `type SceneType = typeof SCENE_TYPES[number]`
- Define `SceneComponentProps` interface: `{ scene: { id: string; type: SceneType; start: number; duration: number; content: Record<string, unknown>; label?: string }; sceneStartFrame: number }` — this is what every scene Remotion component receives
- Define `SceneComponentFactory` type: `React.FC<SceneComponentProps>`
- Define `SceneRegistry` type: `Partial<Record<SceneType, SceneComponentFactory>>`
- Export all types and the SCENE_TYPES array

Create `src/lib/scene-dispatcher.ts`:
- Import `SceneType`, `SceneComponentFactory`, `SceneRegistry` from `./scene-types`
- Create a mutable module-level registry: `const registry: SceneRegistry = {}`
- Export `registerSceneComponent(type: SceneType, component: SceneComponentFactory): void` — adds component to registry. Throws if type already registered (prevents accidental overwrites).
- Export `getSceneComponent(type: string): SceneComponentFactory | null` — looks up component by type string. Returns null if type is not registered (unknown types fail safely, not with throws). Validates that `type` is a valid SceneType before lookup.
- Export `getRegisteredTypes(): SceneType[]` — returns array of currently registered scene types (for diagnostics)
- Export `clearRegistry(): void` — clears all registrations (for testing only)

The dispatcher does NOT import actual scene components — that happens in Phase 2 when components are built. The dispatcher is the registry mechanism. Components call `registerSceneComponent` to register themselves.

Create `src/lib/content-loader.ts`:

Import from node:fs and node:path. Import Zod schemas from `../../content/schemas/index` (relative path from src/lib/ to content/schemas/).

Export `async function loadLesson(filePath: string): Promise<Lesson>`:
- Read the JSON file from disk using `fs.readFileSync` (sync is fine — this runs at build time, not render time)
- Parse JSON with `JSON.parse`
- Validate against `LessonSchema` from content/schemas/lesson.ts
- If validation fails, throw an Error with the Zod error formatted via `error.format()` and the file path
- Return the validated and typed Lesson object

Export `async function loadToolData(filePath: string): Promise<Tool>`:
- Same pattern: read file, parse JSON, validate against `ToolSchema`
- Throw with formatted Zod error on failure
- Return validated Tool object

Export `async function loadSourceFile(filePath: string): Promise<SourceFile>`:
- Same pattern with `SourceFileSchema`

Export `function validateLesson(data: unknown): { success: true; data: Lesson } | { success: false; errors: string[] }`:
- Uses `LessonSchema.safeParse(data)`
- On failure, extracts human-readable error messages from Zod issues
- This is the non-throwing variant for use in validation scripts

Export `function validateToolData(data: unknown): { success: true; data: Tool } | { success: false; errors: string[] }`:
- Same pattern with ToolSchema

Note: The import path `../../content/schemas/index` works because tsconfig has `resolveJsonModule: true` and `moduleResolution: "bundler"`. The content/schemas/ files are TypeScript that will be resolved by the bundler.
